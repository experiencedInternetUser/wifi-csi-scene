# Протокол экспериментов

В сетке сравниваются четыре модели и четыре варианта предобработки CSI на 16 разбиениях данных. Всего выполнено 256 обучений. Основные результаты и структура файлов описаны в [корневом README](../README.md), полные таблицы — в [отчёте](../research/experiment_results.md) и [результатах по доменам](../research/experiment_results_by_domain.md).

### Подготовка данных

В Wallhack используются 44 полные записи: исходный класс 0 — фон, классы 1 и 2 объединены в движение. В 3DO взяты 23 записи `b*` и `w*`, с сохранением меток 0 и 1. Записи сидения и лежания исключены целиком. Отрицательный класс соответствует пустой сцене; неподвижный человек в этих экспериментах не представлен.

Комплексный CSI восстанавливается из CSV как `H[k] = data[2k+1] + j·data[2k]`. Готовые NPY-кэши 3DO не используются: в них найдено ошибочное объединение компонент I/Q. Выбираются 52 поднесущие L-LTF с индексами `[6:32] + [33:59]`, затем вычисляется амплитуда.

Переполнения таймера uint32 исправляются. Пакеты с неправильной длиной CSI или `rx_state≠0` исключаются. Неположительный интервал времени и пропуск более 50 мс начинают новый сегмент. Внутри сегмента амплитуда интерполируется на сетку 100 Гц. Окна длиной 400 отсчётов идут с шагом 400 отсчётов: 4 секунды без перекрытия.

Получено 3045 окон из 67 записей. Источник и время каждого окна сохранены в [windows.csv](results/windows.csv). При подготовке их границы сверяются с [таблицей первичного анализа](../research/analysis/window_features.csv).

### Предобработка

| Название | Преобразование |
|---|---|
| `logamp` | `log(1 + A)` |
| `relative` | `A / max(mean_time(A), 1) − 1`; среднее для каждой поднесущей текущего окна |
| `relative_diff` | Первая разность `relative` по времени; первый отсчёт — ноль |
| `lp20_centered` | Причинный фильтр Баттерворта 4-го порядка, 20 Гц при частоте дискретизации 100 Гц, затем вычитание среднего окна |

Начальное состояние фильтра `lp20_centered` соответствует первой амплитуде каждого канала и сбрасывается перед новым окном. Среднее для центрирования считается по полному окну, поэтому весь алгоритм выдаёт решение после накопления четырёх секунд сигнала.

После каждого преобразования каналы стандартизируются. Среднее и стандартное отклонение считаются по окнам и времени только обучающей выборки; минимальное стандартное отклонение — `1e-4`. Те же параметры применяются к тестовой части.

### Разделение данных

| Набор | Обучение → тест | Число сценариев |
|---|---|---:|
| Wallhack | Один домен → остальные три | 4 |
| Wallhack | Три домена → оставшийся | 4 |
| 3DO | Один день → остальные два | 3 |
| 3DO | Два дня → оставшийся | 3 |
| Wallhack → 3DO | Все домены Wallhack → все дни 3DO | 1 |
| 3DO → Wallhack | Все дни 3DO → все домены Wallhack | 1 |

Списки файлов заданы в [plan.json](results/plan.json). Запись определяется полным путём CSV и целиком относится к одной части. Случайного разделения по окнам нет. Во время обучения перемешивается только порядок мини-батчей внутри обучающей выборки.

Отдельная валидационная выборка не использовалась. В каждом домене Wallhack только одна фоновая запись: выделение её целиком под валидацию оставило бы обучение без фона. Поэтому число эпох и порог выбраны заранее. Ранняя остановка и выбор эпохи по тестовым результатам не применялись.

### Сохранение и проверка

В [results](results) находятся подготовленные массивы, таблицы и результаты каждого обучения. Веса, предсказания и потери связаны общим именем запуска. Параметры стандартизации сохраняются вместе с весами.

`runs.csv` содержит одну строку на обучение. Время `train_seconds` включает цикл обучения, но не подготовку, тестирование и запись файлов. В `results.csv` одна строка соответствует тестовому домену; строка `ALL` объединяет предсказания нескольких доменов одного запуска. Это общая метрика по окнам, а не среднее отдельных доменных метрик.

Команды из корня проекта:

```powershell
python experiments/resume.py --check
python experiments/validate.py
python experiments/report.py
```

`validate.py` проверяет разделение записей и доменов, порядок исходных окон, метки, вероятности и конечность весов. Он пересчитывает 656 строк метрик, независимо проверяет 64 набора параметров стандартизации и повторяет предсказания четырёх архитектур. Результат записывается в [validation.json](results/validation.json).

После перевода комментариев и переноса файлов код получил новые контрольные суммы. Они перечислены в [code_manifest.json](results/code_manifest.json). В `plan.json` и весах сохранены исходные хеши времени обучения. Численные результаты при переносе не менялись; в `runs.csv` обновлены только пути к весам.

Для продолжения прерванного обучения используется `python experiments/resume.py`. Скрипт проверяет план и версию кода, пропускает готовые запуски и повторяет запись при кратковременных блокировках файлов Windows. Общие CSV и JSON обновляются атомарно после каждого завершённого обучения.

### Как читать результаты

Balanced accuracy усредняет полноту двух классов. Precision, recall и F1 относятся к движению; AP рассчитана как average precision. Порог во всех тестах одинаковый — 0.5.

Для сводного сравнения каждый из 16 сценариев имеет одинаковый вес. Если сценарий включает несколько тестовых доменов, используется его строка `ALL`.

Сетка выполнена с одним seed. По ней можно выбрать кандидатов для следующего эксперимента, но разницу между близкими моделями нужно проверять повторными обучениями. Нужны также новые независимые фоновые записи и неподвижные люди. Доля ошибочно классифицированных окон пока не показывает число ложных тревог в час и задержку обнаружения начала движения.
