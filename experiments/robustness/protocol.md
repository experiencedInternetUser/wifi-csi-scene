# Протокол проверки PCA и переноса CSI-моделей

Дата фиксации: 28 октября 2026 года. Протокол составлен до расчёта качества на новых данных.

Исходная ветка нейросетей: `baldezh-6.1-sol-xhigh`, коммит `7092100`. Ветка классических моделей: `origin/baseline`, коммит `d177c46`. Каталог `baseline/` извлечён из этой ветки без изменения её исходников. Новые результаты сохраняются в отдельном каталоге.

## Сравнение на исходных данных

Используются исправленные 3052 окна из `experiments/motion_results`, а не окна прежней сетки. До запуска проверяется фактическое число окон по манифесту. Разбиения: три development-домена Wallhack для обучения, `NLOS/PIFA` для контроля; все домены Wallhack для итогового обучения, 3DO для внешнего контроля. Отбор вариантов PCA — только leave-one-domain-out на development-доменах. Seed: 17, 42, 2026. Контрольные результаты не участвуют в выборе конфигурации.

Сравниваются сохранённая TCN `hampel_lp20`, переобученная TCN той же архитектуры с PCA, логистическая регрессия и LightGBM из baseline, а также одномерный порог. Для классических моделей сохраняются настройки ветки baseline. Дополнительно проверяются два представления признаков: `clean_abs` и `clean_lp_scaled`. Это заранее ограниченное сравнение, без повторения сетки из 256 конфигураций.

PCA обучается по временным отсчётам только обучающих записей после оконной предобработки и стандартизации. Фиксируются K=8 и K=16. В TCN изменяется только число входных каналов первого слоя, остальные слои и режим обучения сохраняются. Для лёгкой модели используются статистики и спектральные признаки главных компонент. Знак компоненты фиксируется по максимальной по модулю нагрузке. Веса, средние, масштабы и матрицы PCA сохраняются. До расчёта внешних метрик добавлен контроль `logreg_standardized`: та же поканальная стандартизация без PCA. Он отделяет эффект изменения масштаба от эффекта проекции; основной отбор классической модели остаётся среди заранее заданных вариантов.

## Проверка новых архивов

Проверяются все записи `day*.zip`, метки сверяются с `day_conf.json`. Смешанные записи не используются для обучения и основных метрик. Начальные и конечные пять секунд исключаются, как у авторов. Для основной проверки берутся не более 24 равномерно распределённых неперекрывающихся четырёхсекундных окон из каждой записи. Это ограниченная выборка пригодности и устойчивости, а не оценка на всех отсчётах. Для неё сохраняются имена записей и точные временные границы.

`wificsi1/2` проверяются по всем MAT-файлам. Основная общая задача — `background` против `walk`. Метка `noactivity` не становится меткой пустой комнаты. Другие активности и локализационные эксперименты учитываются в инвентаризации; их нельзя автоматически приравнивать к обучающей задаче. На запись и класс приходится не более 24 равномерно распределённых неперекрывающихся окон. Записи двух синхронных приёмников одного эксперимента всегда принадлежат одной выборке.

Для TCN заранее фиксируется антенная пара Tx1–Rx1. Atheros: из 56 тонов удаляются два крайних с каждой стороны; остаются индексы −26…−1, 1…26. Intel: 30 групп согласуются с 52 входными позициями интерполяцией отдельно по двум половинам спектра. Этот переход является адаптером представления и не восстанавливает недостающие измерения. При неизвестной ширине канала результат обозначается как проверка на 5 ГГц с условным адаптером 20 МГц.

Амплитуда ресемплируется по реальным временным меткам до 100 Гц. Перед понижением частоты высокочастотный сигнал фильтруется с частотой среза 40 Гц. Разрывы более 50 мс и смены класса разделяют фрагменты; дубликаты миллисекундных меток Intel агрегируются. Окна не пересекают границы класса и записи. Амплитуда остаётся в единицах источника для прямого переноса; безразмерная нормализация проверяется как отдельная конфигурация, обученная на исходном источнике.

## Перенос и повторное обучение

2.4/20: замороженные модели Wallhack проверяются на LabI, LabII и Apartment без подбора порога и без обучения на целевых данных. Отдельно оцениваются ошибки по дням и записям.

5 ГГц: сначала применяются те же замороженные модели. Затем те же архитектуры и предобработка обучаются на Room1/NUC1 и Room1/NUC2 и проверяются на Room2/NUC1 и Room2/NUC2. Эксперименты с общим номером не пересекают train/validation/test. Дополнительная настройка архитектуры по Room2 запрещена. Для повторного обучения используются три seed и фиксированные 20 эпох. Если состав данных не поддерживает такой протокол, ограничение отражается в отчёте вместо подмены теста случайным разбиением окон.

Основная метрика — balanced accuracy при пороге 0.5; дополнительно ROC-AUC, average precision, F1, TPR, FPR и матрица ошибок. Интервалы считаются кластерным bootstrap по записям, для OPERAnet по номеру эксперимента с объединением приёмников. Если независимая фоновая запись одна, интервал не трактуется как оценка переноса на новые фоновые сессии. Пороговая модель подбирает границу только на train.

Все новые модели, преобразования, прогнозы, кривые обучения и таблицы сохраняются. Большие воспроизводимые кэши находятся в `tmp/robustness_cache`; они остаются на диске, но не включаются в Git. Код построения графиков после проверки удаляется по запросу заказчика, готовые PNG и исходные таблицы сохраняются.
